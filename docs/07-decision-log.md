# 의사결정 이력

> 제품 미확정사항과 구현 과정에서 사용자 또는 에이전트가 내린 중요한 결정을 함께 보관한다.

## 기록 규칙

1. 플랜 모드 여부와 관계없이 구현 범위, 아키텍처, 외부 연동, 프로덕션 의존성·버전, 인증·보안, API·DB 계약, 운영·배포에 영향을 주는 결정을 기록한다.
2. 사용자가 내린 결정은 `사용자`, 에이전트가 기존 범위 안의 저위험 세부사항을 선택한 경우는 `에이전트 자동 결정`으로 주체를 명시한다.
3. 범위 확대, 신규 운영 의존성, 보안 방식, API·DB 계약 변경은 에이전트가 자동 확정할 수 없다. 사용자 확인 후 기록하고 구현한다.
4. 결정 ID는 `DEC-YYYYMMDD-NNN` 형식을 사용한다. 결정 하나를 한 행에 기록하며 선택지, 결정 내용, 근거, 영향 범위와 관련 요구사항을 비우지 않는다.
5. 과거 결정은 삭제하거나 사실을 덮어쓰지 않는다. 철회·변경은 새 행으로 추가하고 선행 결정 ID를 `대체/비고`에 연결한다.
6. 명세 변경이 발생하면 이 문서와 별도로 `08-spec-changelog.md` 규칙을 적용한다. `01`~`03` Markdown은 직접 수정하지 않고 원본 스프레드시트를 먼저 갱신한다.
7. 작업 완료 보고에는 새로 기록하거나 적용한 결정 ID를 적는다.

상세한 에이전트 행동 규칙은 저장소 루트의 [`AGENTS.md`](../AGENTS.md)를 따른다.
