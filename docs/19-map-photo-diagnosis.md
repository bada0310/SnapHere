# 사천 게시글의 지도 사진 미표시 원인

확인일: 2026-09-17 01:37~01:40 KST · 결정: DEC-20260917-005 · 범위: 원인 진단

## 결론

게시글과 이미지 자체는 정상이며, **서버의 사진 후보 선정과 앱의 지도 표시 구현에 문제가 겹쳐 있다.** TourAPI 장소 데이터 추가나 Google Maps 키 교체로 해결되는 현상이 아니다.

## 운영 API에서 확인한 사실

- 공개 게시글 목록에서 사천에어쇼 게시글 3개를 확인했다. 등록 시각은 2026-09-16 22:40:01, 22:40:09, 23:24:44 KST이며 모두 최근 24시간·주간·월간 범위에 해당한다.
- 세 게시글의 등급은 모두 `LOW`다. 상세 응답의 `reasonCode`는 모두 `tier.reason.no_taken_coordinate`이며 `countsForHeatmap=false`다. 촬영 위치 정보 부재가 등급 판정 이유다.
- 연결된 사천에어쇼 장소 `plc_1`에는 위도 35.0911816485, 경도 128.0699132182가 있다. 장소 정보는 존재하며 게시글 수는 3으로 응답한다.
- 세 썸네일 URL에 대한 HEAD 요청은 모두 HTTP 200, `image/jpeg`로 응답했다. 썸네일 파일 접근 실패나 사진 후처리 미완료로 확인된 문제가 아니다.
- 전국을 포함하는 지도 범위(west=124, south=33, east=132, north=39)에서 사진 마커 API를 조회했다. `LAST_24H`, `WEEKLY`, `MONTHLY` × zoom 6, 14의 여섯 요청 모두 HTTP 200과 빈 배열이었다.
- 같은 주간 범위의 히트맵은 빈 셀 배열이다. 지역 지도 API의 경남은 `postCount=0`, `representativePost=null`이다.

게시글 상세 GET은 서비스의 조회수 증가 부수효과를 동반한다. 진단 중 게시글 생성·수정, 관리자 집계 실행, 운영 설정 변경은 하지 않았다. 현재 운영 DB와 배포 버전은 직접 조회하지 못했으므로 내부 스케줄러의 성공·실패 여부를 이 결과로 단정하지 않는다.

## 원인 1 — 사진 마커가 히트맵의 등급 제한을 그대로 적용

[MapRepository](../backend/src/main/java/com/snaphere/api/map/MapRepository.java)의 `ELIGIBLE` SQL은 `HIGH`·`MEDIUM` 게시글만 `heatmap_cells`에 집계한다. `rebuildRegions`도 같은 등급 제한으로 지역 통계를 만든다. 게시 직후 갱신도 `PostLocation.eligible()`에서 `LOW`를 제외한다.

[MapService.photoMarkers](../backend/src/main/java/com/snaphere/api/map/MapService.java)는 별도의 공개 사진 후보를 조회하지 않고 `heatmap_cells.sample_post_ids`를 읽는다. 따라서 `LOW` 게시글은 히트맵뿐 아니라 사진 마커에서도 빠진다. 현재 사천 게시글 세 개가 지도 API에서 빈 결과로 나오는 현상은 이 코드 조건과 일치한다.

요구사항 PST-026은 낮음 등급을 뱃지·방문 기록·**히트맵 집계**에서 제외하며 게시와 랭킹 반영은 허용한다. MAP-020은 구역별 대표 게시글의 사진 마커 표시를 요구한다. 히트맵의 제외 조건이 사진 레이어 전체에 적용돼 사진 후보가 없는 상태다. 게시글의 등급을 임의로 올리거나 낮음 등급을 히트맵에 포함시키는 방식으로 고치면 기존 인증 정책이 바뀐다.

## 원인 2 — 홈 지도는 사진 레이어를 연결하지 않음

[HomeScreen](../app/lib/src/features/home/presentation/home_screen.dart)은 `/map/regions`만 구독하며 숫자 말풍선 `countMarker`를 그린다. 사진 마커 provider·뷰포트 조회·썸네일 마커 생성은 홈 화면에 연결되어 있지 않다.

[ApiExploreRepository._mapRegion](../app/lib/src/features/explore/data/api_explore_repository.dart)은 지역 마커 좌표를 `representativePost.place`에서 읽는다. 현재 경남 대표 게시글이 null이므로 좌표도 null이 되고, 홈 화면은 해당 지역 마커를 건너뛴다. 실제 장소에는 좌표가 있어도 지역 대표 응답이 없으면 홈 마커가 생기지 않는다.

## 원인 3 — 별도 지도 탐색 화면에도 썸네일 렌더링 누락

별도 `/map`의 [MapScreen._markers](../app/lib/src/features/map/presentation/map_screen.dart)는 사진 마커 API를 조회하지만 `Marker`에 사진 `icon`을 지정하지 않는다. [PhotoMarker 모델](../app/lib/src/features/map/domain/map_models.dart)이 읽은 `thumbnailUrl`을 사용하지 않아 응답이 있어도 기본 핀이 표시된다. 최대 10개 후보 중 첫 번째만 모델에 남기므로 명세의 3초 사진 교체도 현재 구현되지 않았다.

## 필요한 수정 방향

1. 히트맵의 `HIGH`·`MEDIUM` 정책을 유지하면서, 사진 후보는 정상 공개 게시글·이미지와 유효한 위치를 기준으로 독립 선정한다. 촬영 좌표가 없는 경우 선택 장소의 좌표로 사진을 배치하되 위치 인증 등급은 그대로 유지한다.
2. 홈 지도에 지역·히트맵·사진 레이어와 사진 마커 조회를 연결하고 화면 범위·줌 변경에 맞춰 갱신한다. 사진 레이어와 지역 통계의 표시 기준도 맞춰 3개 게시글이 있는데 0개로 보이는 혼란을 줄인다.
3. 썸네일을 지도 마커 이미지로 변환해 표시하고 탭 시 게시글 상세로 이동한다. 후보 보존, 축소 시 3초 교체·확대 시 고정 규칙도 연결한다.
4. 모의 데이터에서 `LOW` 공개 사진 표시와 히트맵 제외를 각각 검증한 뒤 실제 사천 게시글로 지도 응답과 앱 화면을 확인한다. 운영 수정 적용에는 후속 서버 배포가 필요하다.

이번 진단에서는 수정·배포·재설치하지 않았다.

## 후속 구현 — LOW 제외 유지 (2026-09-17)

후속 결정: DEC-20260917-013. 사용자는 홈 썸네일 표시 구현을 요청한 뒤 LOW 등급까지 표시할 필요는 없다고 명시했다. 이에 위 진단의 사진 후보 확대·서버 분리 수정은 적용하지 않고 기존 HIGH·MEDIUM 사진 후보·히트맵 기준을 유지했다. 현재 사천 게시글 3개는 LOW이므로 계속 제외된다.

홈 화면에 실제 카메라 범위·줌별 사진 마커 조회를 연결하고, API 후보 최대 10장을 보존해 썸네일 말풍선으로 표시한다. 축소 시 3초 로컬 교체, 줌 14 이상 고정, 사진 탭 시 현재 표시 중인 게시글 상세 이동을 구현했다. 다음 사진이 느릴 때 이전 사진과 탭 대상을 유지하고 오류 시 사진 자리 표시를 제공한다. 별도 지도 탐색에서도 같은 렌더링을 사용하고 사진과 동일 셀의 일반 핀 중복을 제거했다. 조회 실패에는 다시 시도 안내를 제공하며 홈 탭 복귀 시 최신 사진·지역을 다시 조회한다.

회귀 테스트 20개·정적 검사·diff 형식 검사를 통과했고 debug APK를 빌드했다. 이미지 렌더링 테스트에서 실제 썸네일 픽셀 포함과 오류 대체 아이콘 생성을 확인했다. 운영 게시글·사진·서버 설정은 수정하지 않았으며 서버 배포가 필요 없는 앱 수정이다. 휴대폰이 연결되어 있지 않아 기기 설치와 실제 지도 화면 확인은 수행하지 못했다.
